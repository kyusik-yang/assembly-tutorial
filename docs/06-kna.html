The kna CLI: Master Database

Query 115K bills, 2.6M votes, and ideal points from your terminal

Overview

The kna (Korean National Assembly) CLI provides offline, instant access to a pre-built master database that integrates 17 Open Assembly API endpoints into a single queryable interface. Unlike the live API (Chapters 3-4), kna works on processed Parquet files - no API key needed, no rate limits, no network latency.

This chapter uses kna 0.7.0

Chapters 6-9 use kna 0.7.0, whose data were collected from the Open Assembly API mostly on 2026-09-25. Release 0.7.0 corrects ten defects in the data shipped up to 0.6.0. Among them, the 17th-20th committee meeting tables stopped at five rows per bill, the roll-call votes of same-name legislators were dropped, party labels were the API’s current party applied to past votes, and cosponsorship edges stopped at 100 names per bill. The default ideal points changed, and dw_ideal_points_20_22.csv is no longer shipped. Before reusing results computed with earlier files, read the 2026-09-26 entry of CORRECTIONS.md.

Feature Live API (Ch 3-4) kna CLI
Bills 16-22nd (per query) 17-22nd (115K pre-loaded, 67 columns in every assembly)
Lifecycle timestamps Requires chaining 4+ endpoints Single row per bill, vetoes folded in
Roll call votes Per-bill, rate-limited 2.6M member-level votes (20-22nd), instant
Member metadata Per-query, current assembly only 1,948 member-terms (17-22nd), with seniority at each assembly
Cosponsorship Per-bill, paginated 1.38M bill-member rows (17-22nd), roles 대표발의 / 공동발의 / 찬성
Asset disclosures Not available 2,928 member-year wealth rows
Ideal points Not available 940 legislator-terms (20-22nd), three series
Propose-reason texts Not available 60,925 bills (20-22nd)
Speed ~2 req/sec Instant (local Parquet)

Installation

Step 1: Install the CLI

pip install kna

Or use pipx install kna which handles PATH automatically. This chapter needs version 0.7.0 or later, which kna --version reports.

Step 2: Get the data

The PyPI package contains the code only. The CLI needs processed Parquet data files hosted via Git LFS:

# Install Git LFS (one-time)
brew install git-lfs    # macOS
# or: sudo apt install git-lfs    # Ubuntu/Debian

git lfs install

# Clone with data
git clone https://github.com/kyusik-yang/kna.git
cd kna
Warning

If you already cloned without LFS, parquet files will be tiny pointer files and kna info will fail. Fix with: git lfs install && git lfs pull

Step 3: Point the CLI to the data

export KBL_DATA=~/kna/data/processed

# Make it permanent
echo 'export KBL_DATA="$HOME/kna/data/processed"' >> ~/.zshrc
source ~/.zshrc

# Verify
kna info

Search bills by title

# Keyword search
kna search "인공지능" --assembly 22

# Combine filters
kna search "부동산" --assembly 22 --status enacted --committee 국토

# By proposer
kna search "조세특례제한법" --proposer 박범계 --assembly 21 -n 30

Filter options:

Option Description Values
--assembly Assembly number 17-22
--committee Committee name (partial match) e.g. 과방, 국토
--proposer Lead proposer name (exact match, joint leads included) e.g. 김영식
--status Status group passed, enacted, reflected, pending, rejected, expired
--kind Bill type 법률안, 결의안, 동의안
--from / --to Proposal date range YYYY-MM-DD
-n Max results (default 20) integer

The status groups are passed (원안가결, 수정가결, 대안반영폐기), enacted (원안가결, 수정가결), reflected (bills with law_reflected = 1), pending (계류중), rejected (부결, 폐기, 철회) and expired (임기만료폐기). A vetoed bill counts as enacted only if it was passed again.

Search propose-reason texts

search queries bill titles. text searches within the full propose-reason text (제안이유) - the substantive rationale behind each bill.

# Find bills mentioning climate change in their rationale
kna text "기후변화" --assembly 22

# Find bills discussing AI regulation rationale
kna text "인공지능 규제" -n 10

This covers 60,925 member law bills of the 20th-22nd Assembly, 60,546 of them with a propose-reason text (99.4%). The 22nd stops with the bills proposed by 2026-02-27.

Shows:

  • Party at election, district and the committees served in that assembly
  • Seniority at that assembly (초선, 재선, …), not the lifetime count
  • Bridged W-NOMINATE ideal point (ideological position) with its vintage
  • Rank within the assembly (← liberal … conservative →)
  • Bill record: bills led, enacted count and rate, promulgated count
  • Top enacted bills with dates

Names are matched exactly, and some legislators share a name. The 22nd Assembly has two members named 박지원, so the CLI lists both MONA_CDs and asks for one:

kna legislator 박지원 --assembly 22
#   2 legislators named 박지원 in the 22nd Assembly:
#   8BF5855P  22nd  더불어민주당  전남광주통합특별시 해남군완도군진도군
#   H7X3372O  22nd  더불어민주당  전북 군산시김제시부안군을

# Pick one by MONA_CD (the name is still required)
kna legislator 박지원 --assembly 22 --mona 8BF5855P

# Without --assembly, one row per term served
kna legislator 추미애
Note

Ideal points are available for the 20th-22nd Assembly only (940 legislator-terms), because the API has member-level votes from the 20th on. For the 17th-19th, the bill record is shown without ideological positioning. The 22nd is in session, and 16 members seated during 2026 are missing from the vote API, so they have no 22nd ideal point yet.

Legislative funnel

How many bills survive each stage of the legislative process?

kna stats funnel --assembly 22
  22nd Assembly · Legislative Funnel (법률안 only)

  Stage           Bills     Rate
  발의           21,022   100.0%  ██████████████████████████████
  소관위 회부    20,966    99.7%  █████████████████████████████
  소관위 상정    17,687    84.1%  █████████████████████████
  소관위 처리     6,396    30.4%  █████████
  법사위 회부     1,729     8.2%  ██
  본회의 의결     1,673     8.0%  ██
  공포            1,555     7.4%  ██

  Each stage counts bills that reached it or a later stage.
  본회의 의결 = floor decision (원안가결, 수정가결, 부결); 공포 = promulgated.

Counting each stage as “reached it or a later stage” keeps the funnel from widening when a bill skips a stage. Committee alternatives (위원장 대안) are never referred to a committee, and bills of the 법제사법위원회 itself skip the 법사위 review.

Data export

Extract filtered subsets for downstream analysis in R, Stata, or Python:

# Health committee bills, enacted only
kna export health.csv --assembly 22 --committee 보건복지 --status enacted

# All 22nd Assembly bills as Parquet
kna export all_22.parquet --assembly 22

# All law bills (법률안) across all assemblies
kna export laws.csv --kind 법률안

Format auto-detected from extension: .csv, .parquet, .tsv. kna export writes bills only, with all 67 master columns. To keep, say, government bills only, filter the export on ppsr_kind == "정부".

Using kna data in Python

The kna package also works as a Python library:

from kna.data import BillDB

db = BillDB()  # reads KBL_DATA, or data/processed in a kna checkout

# Load all 22nd Assembly bills
bills = db.bills(assembly=22)
print(f"{len(bills):,} bills, {len(bills.columns)} columns")  # 21,581 bills, 67 columns

# Load with column pruning (fast)
df = db.bills(assembly=22, columns=["bill_id", "bill_nm", "status", "ppsl_dt",
                                    "enacted", "promulgated", "vetoed"])

# Ideal points: bridged W-NOMINATE by default, in the column ideal_point
ip = db.ideal_points()  # 940 legislator-terms, positive = conservative
dw = db.ideal_points(series="dwnominate")  # or series="wnominate"

# Roll call votes (20th-22nd): party = party at election, party_api = API label
votes = db.roll_calls(assembly=22)  # 545,107 member-level votes
tallies = db.vote_events(assembly=22)  # 1,847 plenary tallies
vetoes = db.veto_events()  # 47 presidential vetoes (재의요구)

# Bill texts
texts = db.bill_texts()  # 60,925 propose-reason texts

# Member metadata (party at election, district, seniority at this assembly,
# committees served in this assembly, sex, birth date)
members = db.members(assembly=22)  # 321 members
spells = db.committee_assignments(assembly=22)  # 1,763 dated committee spells

# Cosponsorship: one row per bill and member, role 대표발의, 공동발의 or 찬성
edges = db.cosponsorship_edges(assembly=22)  # 255,415 bill-member rows

# Asset disclosures (net_worth, real estate, stocks, etc. in 천원)
assets = db.assets(assembly=22)  # 299 member-year wealth rows

# Committee meetings (lowercase columns in every assembly)
meetings = db.committee_meetings(22)  # 137,152 records
Pitfalls with kna 0.7.0
  • There is no kna.load(). Load every table through BillDB, or read the files in data/processed/ directly.
  • Join legislators on MONA_CD, never on the name. It is mona_cd in the member tables and member_id in the roll calls, ideal points and cosponsorship edges. Same-name pairs exist in most assemblies, for example 박지원 in the 22nd.
  • reelection is the lifetime count at the time of collection. For seniority at a given assembly (초선, 재선, …), use term_number or seniority.
  • party is the party at election and keeps the satellite list parties, such as 더불어민주연합 and 국민의미래 in the 22nd. party_current gives the current party of serving 22nd members.
  • ideal_point has positive values for conservatives. Do not flip its sign, as code written for the old aligned column did.

Using kna data in R

library(arrow)
library(dplyr)
library(readr)

# Paths are relative to the root of the kna checkout

# Load master bills
master <- read_parquet("data/processed/master_bills_22.parquet")

# All assemblies (the same 67 columns in every file)
all_bills <- bind_rows(
  lapply(17:22, function(age)
    read_parquet(sprintf("data/processed/master_bills_%d.parquet", age)))
)

# Ideal points: bridged series, positive = conservative (no sign flip)
ip <- read_csv("data/processed/ideal_points_bridged.csv",
               col_types = cols(member_id = col_character())) %>%
  rename(ideal_point = bridged_1d)

# Members, with seniority at this assembly (term_number 1 = 초선)
members <- read_parquet("data/processed/members_22.parquet") %>%
  mutate(first_term = term_number == 1)

# Bill texts
texts <- read_parquet("data/processed/bill_texts_linked.parquet")
